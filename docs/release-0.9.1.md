# 0.9.1 说明与当前验收

技能、安装脚本与默认工作流面向 **Codex**。其他 AI harness 需要自行适配技能加载、本地执行、权限/路径并独立验证。这是一份公开前源码候选，尚未授权公开发布或改变仓库可见性。

## 本次改动

- 新增公开复现脚本 `scripts/verify_matrix_display.py`：默认只重建独立固件、生成带探针 48 元件图、核对全部 29 个期望网络并准备按键组，不启动 Proteus。原生执行必须显式加 `--execute-native` 与新绝对 ASCII TEMP；截图再单独加 `--capture`。
- 新布局将 DS1 端子文字错开两行，MCU/探针沿真实引脚出口使用短直线，X1 文字让开走廊。保存网络和模型，保留 35 条保守文字估算警告。
- 新公开接口 `terminal_label_position(id)` / `set_terminal_label_position(id, position)` 读取/设置文字绝对原生整数锚点（100000/mm）；`None` 恢复当前默认锚。保留字体、样式和电气身份，未知/歧义 ID、布尔/浮点或超出 int32 的坐标拒绝，不再让示例访问私有端子字段。
- Session 构造及 Simulation.open() 在原生启动后遇到 BaseException 时，只清理各自确切的 Popen 并重抛原异常。分组报告保留构造失败时的启动 PID/关闭状态；检查点写盘失败不能吞掉正在传播的中断。
- 单窗口截图依赖声明为可选 `Pillow>=11.2.1`，并核对明确的 `ImageGrab.grab(window=...)` 参数；不回退到桌面截图。普通文件操作不导入 Pillow。安装及官方来源见 [原生参考](../skills/proteus86-files/references/native.md)。

## 两种复现模式

使用不同的新输出目录；不要在准备成功的同一个目录上再运行原生模式：

```powershell
python scripts/verify_matrix_display.py --output-dir artifacts/matrix-prepare-091-NEW
python scripts/verify_matrix_display.py --output-dir artifacts/matrix-native-091-NEW --execute-native --temp-dir D:/Proteus86Temp/matrix-091-NEW
```

第二条可加 `--capture`。TEMP 与输出目录都必须新建、彼此独立且互不嵌套；TEMP 是调用者显式选择的绝对 ASCII 路径。示例选择 D 盘，以免写入系统盘。文件准备将临时文件放在自己的输出中，不默认使用系统 TEMP。需要本地已授权 Proteus 库/模板；不分发它们。

文件模式的 `passed=True/status=prepared/scope=file_contract_preparation_only` 仅证明文件准备完成，`native_run_completed=False`、`simulation_executed=False`。原生模式要求真实计时、输入回读、诊断、显示/响应计数断言与自有进程清理，实际样本数写入本次报告。输出保留固件构建、原始生成图、验证合同、分组和阶段检查点；请求运行不等于已经观察到进程或推进计时。

## 例程文件生成耗时

独立 Python 3.12.14 环境下，以同一当前核心、模板和显式固件，32/48 元件的旧/新例程布局策略各重复三次，共 12 次交错生成。完整逻辑/物理网络、模型和固件等价；结果为：

| 元件数 | 旧策略中位数 | 新策略中位数 | 耗时下降 |
|---|---:|---:|---:|
| 32 | 1.89940 s | 1.62266 s | 14.57% |
| 48 | 2.28485 s | 1.95703 s | 14.35% |

计时围绕 `generate()`，包含布线/保存/重读/核网/预览/结果写入，另行等价性检查不计入时间。该测量是同核心下的例程策略比较，不能称为版本间通用核心提速、任意电路耗时保证或原生仿真加速。描述性统计见[本轮脱敏记录](validation/v0.9.1.json)；它的环境与完整回归/原生验收分别记录。

## 限制与记录

新原生流程仍是单键顺序分组，不是同时绑定 16 键。八位显示跨扫描相位重建，每次至少两轮完整结果一致；实际采样窗口有限，不是原子帧、电压/电流/亮度或实体硬件验证。每键场景为稳定按下 80 ms 再保持 120 ms；K0 另有 3 ms 脉冲、三轮 2/3 ms 抖动与稳定释放后重按。其他固件和更长/更快场景需独立期望与验证。

中断/取消/失败的部分结果保持整体未通过。构造清理、日志或部分初始化计时不等于功能验收；写盘失败会保留可用错误而不将原中断吞掉。强制结束 Python 或断电无法执行清理。所有原生操作只管理本次拥有的进程，游戏期间仅做文件工作。
