# 0.9.2b1 双平台 Beta

Codex 与 DeepSeek Harness 使用同一套文件、固件、布线、原生会话及数字验证核心；两套短入口只负责技能发现、工具注册、目录权限和长任务跟踪。沿用现有私有仓库，本说明不授权公开发布或修改仓库可见性。

新增共享结构化接口、受目录约束的 stdio MCP、可查询/等待/取消的独立原生任务，以及同源双平台技能安装。既有 Python API 与 CLI 保留。没有增加运行时必需依赖；截图仍需要可选 Pillow，原生运行仍需要用户自己的兼容 Proteus 安装。

发布包修复了仅安装 wheel 时缺少矩阵例程和验收辅助脚本的问题。构建时把明确列出的现有辅助源码映射到唯一的 `proteus86_support` 命名空间，并包含独立编写的矩阵 A51/HEX；不安装通用的顶层 `examples` / `scripts` 包，不复制仿真核心，也不收录其他本地探测脚本。wheel 增加 `proteus86-mcp` 命令；技能和两套安装入口由审核源码 ZIP 提供，见 [安装与打包](packaging.md)。

打包前的源码适配已通过官方 DeepSeek V4.1 Flash / low 实际会话、16 键顺序 5/5/5/1 验收、25 次显示重建、646 个原生 SDF 样本、运行截图和自有进程清理。Codex 使用同一分发器的实际原生路径也已验证。失败的同步 RPC 超时、早期异步起仿与清理记录保留失败状态；确切范围见 [适配记录](validation/dsh-parity-20261028.json)。

最后打包阶段只做文件回归、源码审计、离线构建、隔离 wheel 安装、MCP 文件调用和两个独立技能安装检查，没有启动 Proteus、操作桌面或重启服务。辅助脚本仅调整导入路径，原验证函数体与已审核版本比较。检查结果见 [打包记录](validation/release-v092b1-20261028.json)。这些检查不能替代安装后原生仿真。

Beta 的已知边界：dsh 网页配置及技能发现已检查，网页内实际交互未验证；dsh 自带 Windows shell 的 ACL 授权故障仍未修复，共享 MCP 不会改变其沙箱模式。安装后 wheel 的原生运行待独立验证。原有未知格式、出线、固件哈希、进程所有权和本机版本保护继续适用。PCB、任意波形/电压/模型内存采集及实物验证仍不支持。

只分发审核源码、独立例程和许可。厂商程序/库/模型/模板、课程资料、私有固件、个人信息、凭据、机器安装定位清单、原生工程和截图均排除。保留 [MIT 及第三方归属](../THIRD_PARTY.md)，历史 0.9.0/0.9.1 报告不改写。
